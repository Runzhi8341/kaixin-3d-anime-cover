# 开心科技封面 Skill 当前设计流程

这份流程是给后续执行者看的“操作总图”。目标是稳定生成用户已确认喜欢的爆款科技封面：3:4、强标题、真人脸部识别、非写实角色身体、荒诞但秒懂的世界场景。

## 1. 输入识别与资料检索

先判断用户给的是什么任务：

- 已有脚本文案、文章或链接：判断用户是否明确指定标题；未指定时才进入标题提炼。
- 用户只给了“要做封面的标题”：也要触发本 Skill。先用 `aihot` 搜索标题所指的近期 AI 产品、发布或事件，再用检索结果理解产品功能和事实边界；无可靠结果时，索要链接、脚本或一句背景说明，不得硬猜。
- 要找 AI 产品话题：先用 `aihot` 找近期 AI 产品动态，优先选能被一秒视觉化的产品，不选抽象行业观点。
- 给了人物照片：人物照片是脸部身份锚点，不是普通参考图；没有照片不代表可以自动假定人物脸部特征。
- 用户说“用真人”或“用我的真人形象”：请其提供本次任务要使用的人物照片；照片仅用于当前任务，不保存为默认参考，也不复用于后续任务。
- 给了满意样张：必须复刻样张的黄橙 3D 粗斜招牌字和顶部压迫式排版；禁止退回本地脚本后期字。

默认平台为小红书、抖音、视频号通用封面，统一 3:4。

## 2. 标题确认关卡

先区分两种情况：

- 用户明确说“标题是……”或“就用这个标题”：先判断长度。若超过排版安全长度，必须从原题和文案提炼 1 个推荐短标题，再让用户选择保留原标题或使用提炼标题；不能直接把长标题当成已确认的封面标题。
- 用户没有明确指定标题：基于已确认内容给 3 个候选，询问用户是否满意；用户不满意时继续修改，直到确认一条最终标题。

标题未确认前，禁止进入素材确认、人物、角色、场景、构图、提示词或出图。

中文主标题超过 8 个字、或在手机缩略图中无法舒适排进两行时，一律视为长标题。先给 1 个从原题提炼的推荐封面短标题，建议 3–6 个字、最多 8 个；然后让用户明确选择：`保留原标题` 或 `使用提炼标题`。只有用户选择后才锁定标题：前者逐字保留原题，后者使用被选中的短标题。标题要像手机缩略图里的第一视觉锤。

优先格式：

- 产品名 + 结果：`Codex解锁`
- 功能隐喻：`代码地图`
- 口语结果：`一键建站`
- 对象 + 强动作：`GPU组队`
- 结果 + 场景：`笔记变视频`

副标题通常放绿色粗斜体，承担产品名或第二层解释，例如 `Mesh LLM`、`Perplexity`、`不限时开工`。

## 3. 素材确认关卡

最终标题确认后，确认用户是否提供：

- 人物真实照片
- 产品或网页截图
- 真实 Logo
- 品牌色、样张或其他必须保留的素材

用户提供人物照片时，人物项直接记为“使用本次提供的人物参考”；仍必须等待截图、Logo、品牌色和样张的答复后才能进行场景设计。真实 Logo、截图和 UI 后期合成，不能让模型重绘。

用户明确没有人物真实照片时，先说明不能保证真人身份相似；若用户没有指定人物设定，可使用非特定的中国男性角色作为保底。用户未答复前，禁止自动生成中国男性、透明眼镜或其他人物特征。

## 4. 人物设计

有照片时，人物采用“真实脸部身份锚点 + 非写实角色身体”。只使用用户在本次任务中提供或明确授权使用的照片，不建立默认人像库。无照片时，按用户指定的角色设定，或采用已说明的保底角色。

必须保留：

- 照片中可见的脸型
- 眉眼距离
- 鼻子和嘴型
- 发型、眼镜等可见标志
- 肤色和年龄感

人物参考不得出现的回退：

- 在用户已提供照片时，以陌生脸或模型自行创造的人物代替照片中的人物
- 未经用户提供或明确授权，擅自调用、保存或复用任何人物照片

可以改变：

- 表情，必须更强烈
- 身体材质，优先 3D 软胶玩具、纸雕、手办、木偶
- 服装和职业
- 动作和所处世界

失败线：

- 脸像陌生卡通娃娃
- 只是写实真人半身照
- 人物像讲师站台
- 身体没有角色化

## 5. 角色与世界场景

每张封面先完成这个转换：

`产品功能 → 角色职业 → 世界场景 → 一秒剧情`

不要从“科技背景”开始。场景必须是一个有记忆点的舞台。

每个方向先写完这张“剧情卡”，再允许写生图提示词：

- 输入：用户给产品的什么材料或动作，例如照片、头像、模型文件。
- 角色：人物在故事里具体是谁，不得是普通讲解员。
- 世界：一个不能替换成办公室或普通工厂的大世界。
- 转化事件：画面中正在发生的、能被看见的物理变化。
- 结果：用户一眼能看到产品帮他得到什么。

“摆一个打印机、站一个人物、放几个手办”不是剧情卡，直接判失败。

常用映射：

| 产品功能 | 角色 | 世界场景 | 剧情 |
| --- | --- | --- | --- |
| 解锁、提速 | 守关人、爆破手、赛车手 | 长城、城门、火箭场、峡谷赛道 | 剪断锁链、打开城门、冲出限制 |
| 代码理解、回放 | 探险家、考古学家 | 金字塔、沙漠遗迹、地下迷宫 | 挖出代码地图，点亮代码迷宫 |
| 分布式、多设备 | 队长、登山指挥官、宇航员 | 山顶、太空站、月球、云海 | 把设备连成 AI 算力网络 |
| 数据、图表 | 魔法师、教授、炼金术士 | 魔法学院、课堂、炼金室 | 把表格变成 3D 图表 |
| 分析、预算、侦测 | 侦探、会计侠 | 城市天台、侦探事务所、金库 | 用红线和放大镜找出消耗线索 |
| 内容生成 | 导演、魔术师、工厂老板 | 电影片场、内容工厂、宇宙隧道 | 素材变视频或内容流水线 |
| 建站、部署 | 工头、建筑师、工程车司机 | 城市工地、积木都市、未来港口 | 把窗口推成网站楼群 |
| 照片转 3D 模型、生成手办 | 玩具炼金师、模型列车长、潮玩探险家 | 模型峡谷、肖像星球环、手办云端列车 | 照片穿过建模之门变成发光网格，再落成可打印手办 |

同一批 5 张封面里，至少 4 张使用不同大类世界场景。

## 6. 字体与版式

爆款大头模式直接复刻已确认满意样张的图文一体 3D 招牌字，不使用 `compose_cover.py --treatment blast` 作为正式标题：

- 顶部 25%–35% 被主标题强占
- 主标题黄到橙 3D 渐变，有挤压厚度和亮面
- 极粗、略斜、块面感强，整体像一块招牌压在画面顶部
- 厚黑内描边和黑色投影
- 粗白外描边
- 外圈蓝光、白光或橙光，不是单薄暗黄光
- 绿色产品副标题贴在主标题下方或嵌入标题组
- 产品名、功能解释和证据短语都应嵌在同一套 3D 招牌字系统里
- 用户确认的长标题必须逐字完整，允许上下两行或沿场景透视拆行；标题必须像场景内的实体招牌，受环境光、投影、遮挡和透视影响，不能像后贴的平面文字。

禁止：

- 普通雅黑、宋体、PPT 字
- 脚本 `blast` 风格的浅黄平面大字
- 左上角小胶囊 kicker
- 细小青色副标题
- 标题单字孤行
- 主标题太小
- 副标题抢主标题
- 灰蒙遮罩把画面压脏
- 漏掉、改写或裁掉用户确认标题的任何汉字或标点
- 把标题单独悬在顶部，与人物、门洞、道具和场景没有物理关系

## 7. 画幅和输出

默认输出：

- 3:4
- 推荐标准尺寸：1242×1656 或 1080×1440
- 小红书、抖音、视频号统一使用 3:4

如果生成工具给出非标准尺寸，交付前必须整理成 3:4 标准文件，并保存到 `cover-output/`。

## 8. 自检清单

交付前逐张检查：

- 脸：能认出参考人物吗？
- 身体：是否非写实角色化，而不是讲师半身照？
- 表情：是否足够夸张、清晰？
- 标题：手机缩略图能不能一眼读？
- 字体：是否是黄橙粗斜招牌字，而不是普通字体？
- 场景：有没有世界舞台，而不是办公室/机房/报表墙？
- 剧情：能不能说出“输入是什么、发生了什么、最后得到什么”？
- 标题选择：长标题是否已先给提炼版，并由用户选择保留原标题或使用提炼标题？
- 标题完整性：用户选择的最终标题是否每个汉字和标点都完整、正确、可读？
- 标题融合：标题是否受场景透视、光影、遮挡和道具关系影响，而非后贴平面字？
- 产品：是否能对应产品功能？
- 道具：至少有 2 个产品/AI 道具或抽象工具符号？
- 比例：是否为 3:4？
- 流程：标题是否已确认，人物照、截图和 Logo 是否已确认或明确缺失？

任一关键项失败，不得当正式成品交付，只能重做或标为备用。

## 9. 当前已验证的高质量方向

近期测试中确认更接近目标的方向：

- `Codex解锁`：长城代码守关人，在夜色长城剪断 5H 锁链。
- `代码地图 / Mindwalk`：金字塔代码考古探险家，挖出 Git 分支石板。
- `GPU组队 / Mesh LLM`：山顶算力基站队长，把 GPU、卫星和笔记本连成 AI 网络。
- `AI画图表 / Flint`：魔法学院数据教授，把表格羊皮纸变成 3D 图表。
- `额度看板 / Perplexity`：城市天台 AI 侦探，用红线、金币和放大镜破获模型消耗案。

这些不是固定模板，而是质量基准：后续可以换题材、换场景，但不能低于这类“角色清楚、场景有记忆点、产品隐喻秒懂”的标准。
